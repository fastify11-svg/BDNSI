# BDNSI Institute Platform

BDNSI is a Laravel + React/Inertia + MySQL platform for center-driven student registration, academic documents, payments/credit, results, certificates, and public verification.

## Repository contract

`main` is the clean development source of truth. It is **not** the file set that should be extracted directly into `public_html`.

The repository contains application source, migrations, tests, and CI. Production dependencies and the shared-hosting layout are generated by GitHub Actions from an exact commit.

## Golden shared-hosting package

The supported manual deployment output is:

- `BDNSI_PUBLIC_HTML_READY.zip`
- `BDNSI_database.sql`
- SHA-256 checksum files

The ZIP is generated in the same flat `public_html` layout proven on the live test deployment. It already contains production Composer dependencies (`vendor/`), compiled Vite assets (`build/`), Laravel runtime source, a production `.env` template, a fresh MySQL dump, root `index.php`, hardened `.htaccess`, and the storage-file fallback.

Hosting does **not** need Composer, npm, SSH, `php artisan storage:link`, or a document-root change.

Deployment is intentionally limited to:

1. Extract `BDNSI_PUBLIC_HTML_READY.zip` directly into `public_html`.
2. Import `BDNSI_database.sql` into a fresh MySQL database.
3. Edit `.env`: `APP_URL`, `DB_HOST`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`.
4. Open the site and change the generated initial admin password after first login.

See [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md).

```text
  → Student registration
  → Documents
  → Pricing / payment / credit
  → Result
  → Certificate
  → Public verification
```

## Development workflow

Changes go through automated CI before they reach `main`. CI validates Composer metadata, installs dependencies, runs a real MySQL migration/seed cycle, executes the PHP regression suite, compiles frontend assets, and runs browser smoke/e2e coverage.

The shared-hosting release builder then produces a deployment artifact from the exact source commit. Build outputs, passwords, `.env` secrets, local runtime files, AI-agent state, scratch scripts, and historical implementation reports do not belong in `main`.

## Security rules

- Never commit a real `.env`, database password, payment/SMS credential, SSH key, or production backup.
- Production configuration belongs only in the deployed `.env` or an authorized secret store.
- Financial mutations must remain transactional and idempotent.
- Protected documents and tenant-scoped resources must remain authorization-checked.
- The release package blocks direct web access to Laravel source/runtime directories and sensitive root files.
